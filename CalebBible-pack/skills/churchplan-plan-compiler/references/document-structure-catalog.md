# 문서 구조 카탈로그 — 계획서 9요소·슬라이드 10장·비전 한장·보강 안내·디자인 톤

> #10 하위 스킬이 공유하는 문서 구조 패턴. 콘텐츠를 *지어내는* 카탈로그가 아니라, 앞 산출물의 확정 내용을 *어느 자리에 전사*할지의 골격이다. 새 본문·수치·표어를 만들지 않는다.

## 1. 목회계획서 본문 = 정확한 9요소 (01 라인 316 — 고정·콘텐츠 생산 금지)
계획서 본문 장 구성은 아래 9요소로 **고정**한다. plan-document-composer는 장을 새로 기획하지 않고, 각 장을 해당 출처에서 *전사*한다.

| # | 장(key) | 출처 | 전사 내용 |
|---|---|---|---|
| (도입) | 지난해 돌아봄 *(선택)* | diagnosis.json | 있을 때만 — 현황 요약(없으면 생략) |
| 1 | 표어 | vision.chosen.theme | 표어 그대로 |
| 2 | 방향 선언문 | vision.direction_declaration | 목사의 선언문 **그대로**(AI 재작성 금지) |
| 3 | 3축 목표 | goals.axes | 영성·전도·양육 목표·지표 |
| 4 | 설교계획 ★ | sermon-plan.series + weeks | 분기 시리즈 개요 + 52주 요약(핵심 장) |
| 5 | 핵심행사 ★ | events.signature_events | 핵심 행사 기획안 요약 + 행사–목표 지도(핵심 장) |
| 6 | 실행계획 | action.department_table | 부서별 실행 요약 |
| 7 | 예산 | resource.budget_plan | 예산 배분(비율·증감 — 절대 금액 금지 계승) |
| 8 | 조직 | resource.org_plan | 조직 배치·리더 양성 |
| 9 | 점검계획 | review.scorecard + schedule | 분기 점검 리듬·반기 수정일 |

- **설교(4)·행사(5)가 핵심 장**(성도가 1년 내내 만나는 것 — 설계원칙2).
- **캘린더는 본문 9요소가 아니다** — bundle 별첨(연간 사역 캘린더 파일 참조).
- 각 장은 *요약 전사*(원본 표·기획안은 bundle에서 상세).

## 2. 당회/제직회 요약 슬라이드 (10장 내외 — 표어·설교 흐름·핵심 행사 중심)
청중 = 당회/제직회(의사결정자). 톤 = 요약·결정 중심. 02 라인 225.

| 장 | 제목 | 내용(전사) |
|---|---|---|
| 1 | 2027 표어 | 표어 + 핵심 본문 |
| 2 | 지난해 돌아봄 *(선택)* | diagnosis 있을 때 — 강점·돌봄점 |
| 3 | 올해 방향 | 방향 선언문 핵심 |
| 4 | 3축 목표 | 영성·전도·양육 한눈 |
| 5 | 설교 흐름 ★ | 분기 시리즈 4개 |
| 6 | 핵심 행사 ★ | 핵심 행사 3~5개 |
| 7 | 연간 캘린더 한눈 | 분기 흐름 |
| 8 | 예산·조직 | 비율·증감 / 리더 양성 |
| 9 | 점검 리듬 | 분기 4회 + 반기 수정일 |
| 10 | 동참 초청 | 함께 세우는 한 해 |

- 7~12장 범위 허용(10장 내외). 슬라이드는 *불릿 요약*(본문 복붙 금지).

## 3. 성도 공유용 비전 한 장 (은혜의 초청 톤)
청중 = 성도(전 교인). 톤 = 초청·은혜(율법적 압박 아님). 01 라인 324.
- **표어** + **핵심 본문**(vision.core_scriptures 전사)
- **핵심 방향 3가지**(쉬운 말로 전사 — 새 교리·약속 지어내지 않음)
- **동참 초청** 한 단락(성도가 한 해 어떻게 함께하나)
- 숫자·예산·조직은 넣지 않는다(성도용은 방향과 초청만).

## 4. 옵션2 보강 안내 (살아 움직이는 마무리 — 끝이 아니라 시작)
02 라인 241·245~255. 워크샵 패키지에 함께 담는다.
- **귀가 후 실측 대상**(`verify_seeds`): review.json의 `verify_at_review:true` 지표 + goals 신뢰 '하' 항목을 모아 "이 항목은 추정입니다 — 주보·결산서·교적부로 또렷이 하세요".
- **분기 자동 점검 안내**: review.schedule.auto_reminder 구조 전사(원하는 목사만).
- **다음 다리**: "#12 plan-reinforce — 있는 만큼만 올리면 추정→실측, 계획서 v2로 자랍니다."
- 톤: 부족을 비난하지 않는다("계획이 스스로 자란다"는 격려 틀).

## 5. 디자인 톤 일관성 (교회별 — hardcoding 금지)
- **교회명·로고·톤은 목사 1회 입력**(박사님 개인 톤·특정 교단 hardcoding 금지 — 누구든 사용).
- 표어를 모든 문서의 머리에 일관 배치(표어 기반 톤 일관성·기능④).
- 기본 팔레트는 절제된 따뜻한 톤(세피아 계열 머리글). 교회 로고/색이 있으면 우선.
- 본문 폰트는 가독성 우선(나눔명조 계열). docx는 후편집 가능하게.
