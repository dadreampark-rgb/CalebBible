# Orchestration Trace 양식 (응답 강제 구조)

> 대표 스킬이 사용자 명령에 응답할 때 반드시 이 4부 구조로 표시(기준 #10). inline 시뮬레이션 단독 금지.

```
## (a) 발동·분류
- 발동 마스터: churchplan-review-rhythm
- 상속: 목표·지표(#3 axes[].goals.indicators — baseline·target·by·signal_only·신뢰)·자원 지속가능성(#8 warnings·demand_gaps·pastor_time)
- 목사 1회 입력: 분기 점검 시점 / 반기 수정일(6·7월) / 자동 리마인드 사용 여부 (생략 시 기본값)

## (b) 호출 Trace
| 순서 | 하위 스킬 | AI Agent | 한 일 | 산출 |
|------|-----------|----------|-------|------|
| 1 | scorecard-builder ★ | 신호등을 세우는 자 | 지표→분기 신호등(미래값 비움·돌봄 프레이밍·흐린 지표 실측 표시) | scorecard |
| 2 | monthly-checkup | 5분을 지키는 자 | 월간 1p(핵심 지표만) + 목자 소진 체크 | monthly_checkup |
| 3 | red-signal-responder | 빨강을 돌보는 자 | 빨강 대응 시나리오(정죄 아닌 돌봄) | red_signal_scenarios |
| 4 | review-scheduler | 리듬을 못박는 자 | 분기 4회+반기 공식 수정일+분기 어젠다+(선택)리마인드 구조 | schedule |
| (확정 후) 5 | rhythm-renderer | 점검표를 짓는 자 | 스코어카드·월간표 html+xlsx | 점검 파일 |
| 6 | fidelity-guard | 점검을 지키는 자 | 미래값 둔갑·돌봄 프레이밍·반기일·상속 검증 | 검증 리포트 |

## (c) 하위 산출물 (각 별도 섹션)
### 🚦 분기 신호등 스코어카드 (scorecard-builder — 점검 전 status 비움)
### 🗓️ 월간 1페이지 점검표 + 목자 소진 체크 (monthly-checkup)
### 🔴 빨강 지표 돌봄 대응 시나리오 (red-signal-responder)
### 📆 연간 점검 일정 + 분기 어젠다 + 반기 공식 수정일 (review-scheduler)
### 📋 점검 스코어카드·월간표 파일 (rhythm-renderer — 목사 확정 후에만)
### 🛡️ 점검 리듬 검증 (fidelity-guard)

## (d) 마스터 통합 + 점검 리듬 확정 초대 (별도 섹션)
### 🚦 분기 신호등 한눈 요약 (어느 지표를 언제 — 색은 점검 시점에)
### 🗓️ 월간 5분 점검 (목자 자신을 포함해)
### 📆 연간 점검 리듬 (분기 4회 + 반기 6~7월 공식 수정일)
### 🙏 "점검은 채찍이 아니라 돌봄입니다. 분기 점검 시점과 반기 수정일을 언제로 못박으시겠습니까?"
   — [목사 검토·확정 HITL 대기. 일정·반기일·신호등 기준 확정 전에는 최종 점검표를 렌더하지 않는다.]
### (확정 완료 후) 📋 점검 스코어카드 + 월간 점검표 (html + xlsx) + 연간 점검 일정
### ➡️ 다음 단계: plan-compiler(#10)로 전달

## 원칙
- **(d)에서 반드시 확정을 기다린다.** 점검 일정·반기 수정일·신호등 기준 제시와 최종 점검표 렌더 사이에 목사의 확정 HITL이 있다.
- **미래 점검값을 지어내지 않는다** — 신호등 색·status는 점검 시점에 목사가 채운다(전 섹션).
- **점검은 돌봄이지 채찍이 아니다** — 정죄·문책 어휘 금지(care-framing 계승).
- **반기 6~7월 공식 수정일을 못박는다** — 계획은 갱신으로 산다(01 라인 310).
- 실제 지표 수집·자동 발송은 #9 밖(점검 시점 목사·교회 환경 운영). #9는 *살아 움직일 틀*까지.
- fidelity-guard 실패 시 (c)에 위반 노출, 해당 분석 재실행(임의 보정 금지).
```
