# Orchestration Trace 양식 (응답 강제 구조)

> 대표 스킬이 사용자 명령에 응답할 때 반드시 이 4부 구조로 표시(기준 #10). inline 시뮬레이션 단독 금지.

```
## (a) 발동·분류
- 발동 마스터: churchplan-ministry-calendar
- 상속: 표어(vision)·52주 설교(#4)·핵심/정기 행사(#5)·목표 마일스톤(#3)
- 목사 1회 입력: 쉼 필요 주간(휴가·안식)·올해 캠페인(통독·기도시즌 등)·피할 지역/학사 일정

## (b) 호출 Trace
| 순서 | 하위 스킬 | AI Agent | 한 일 | 산출 |
|------|-----------|----------|-------|------|
| 1 | layer-merger ★ | 한데 모으는 자 | 52주 격자에 설교·행사·정기·캠페인·마일스톤 통합 배치 | weeks[] |
| 2 | season-aligner | 시즌에 맞추는 자 | 분기 시즌(1Q~4Q) 정렬 점검 | season_alignment[] |
| 3 | tri-consistency-checker | 한 방향을 잇는 자 | 설교–행사–사역 3중 정합·간극 | tri_consistency[] |
| 4 | overload-marker | 밀집을 비추는 자 | 연속 고강도·행사 밀집 자동 표시 | density_warnings[] |
| 5 | sabbath-protector | 안식을 지키는 자 | 휴식 주간 보호 + 상속 부하 통합 | rest_plan[]·inherited_warnings |
| (확정 후) 6 | calendar-renderer | 달력을 짓는 자 | 통합 캘린더 html(분기/월/주+히트맵)+xlsx | 캘린더 파일 |
| 7 | fidelity-guard | 통합을 지키는 자 | 52주 무결성·상속 충실·밀집/안식 검증 | 검증 리포트 |

## (c) 하위 산출물 (각 별도 섹션)
### 🧩 52주 통합 격자 (layer-merger)
### 🍂 시즌 정렬 점검 (season-aligner)
### 🧭 설교–행사–사역 3중 정합 (tri-consistency-checker)
### 🔥 밀집·연속 고강도 경고 (overload-marker)
### 🛌 안식 주간 보호 + 총 부하 (sabbath-protector)
### 🗓️ 통합 캘린더 (calendar-renderer — 목사 확정 후에만)
### 🛡️ 캘린더 검증 (fidelity-guard)

## (d) 마스터 통합 + 재배치·확정 초대 (별도 섹션)
### 🗂️ 52주 한눈 요약 (분기별 강단·행사·사역 흐름)
### 🔥 밀집·소진 위험 주간 (어디가 무거운가)
### 🛌 안식 주간 제안 (어디서 쉴 것인가 — 여백도 계획)
### 🙏 "밀집·소진 위험 주간이 여기 있습니다. 어느 주간을 비우고/안식으로 보호하시겠습니까?"
   — [목사 검토·확정 HITL 대기. 확정 전에는 최종 캘린더를 렌더하지 않는다.]
### (확정 완료 후) 🗓️ 통합 연간 캘린더 (분기·월·주 보기 + 부하 히트맵)
### ➡️ 다음 단계: action-planner(#7)·plan-compiler(#10)로 전달
```

## 원칙
- **(d)에서 반드시 확정을 기다린다.** 밀집·안식 제시와 최종 캘린더 렌더 사이에 목사의 재배치·확정 HITL이 있다.
- 달력을 꽉 채우는 것을 성공으로 삼지 않는다 — 여백도 계획이다(전 섹션).
- 상속되지 않은 주차·설교·행사·캠페인을 캘린더가 지어내지 않는다(fidelity-guard 상속 id 충실 검사).
- 마일스톤은 *표시*만 — 분해·담당 배정은 #7. (#6은 #7 영역을 침범하지 않는다.)
- fidelity-guard 실패 시 (c)에 위반 노출, 해당 분석 재실행(임의 보정 금지).
```
