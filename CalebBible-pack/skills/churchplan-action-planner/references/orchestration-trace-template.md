# Orchestration Trace 양식 (응답 강제 구조)

> 대표 스킬이 사용자 명령에 응답할 때 반드시 이 4부 구조로 표시(기준 #10). inline 시뮬레이션 단독 금지.

```
## (a) 발동·분류
- 발동 마스터: churchplan-action-planner
- 상속: 3축 목표(#3)·통합 캘린더(#6 마일스톤·행사·시즌)·행사 blueprint(#5)
- 목사 1회 입력: 교회 사역 부서 구조

## (b) 호출 Trace
| 순서 | 하위 스킬 | AI Agent | 한 일 | 산출 |
|------|-----------|----------|-------|------|
| 1 | milestone-decomposer ★ | 행동으로 푸는 자 | 목표→분기 마일스톤→월별 행동 분해 | actions[](milestone·monthly_steps) |
| 2 | department-router | 부서로 보내는 자 | 부서 배치 + 목적·시기·담당·자원 | actions[].department·department_table |
| 3 | gap-flagger | 공백을 드러내는 자 | 담당·자원·시기 미정 플래그 | gaps[]·actions[].flags·warnings(중복배정) |
| (확정 후) 4 | action-renderer | 실행표를 짓는 자 | 부서별 실행계획표 md+xlsx | 실행계획표 파일 |
| 5 | fidelity-guard | 실행을 지키는 자 | 근거·공백 정직·캘린더 정합 검증 | 검증 리포트 |

## (c) 하위 산출물 (각 별도 섹션)
### 🧩 목표→행동 분해 (milestone-decomposer)
### 🏛️ 부서별 배치 (department-router)
### 🕳️ 공백·중복 플래그 (gap-flagger)
### 📋 부서별 실행계획표 (action-renderer — 목사 확정 후에만)
### 🛡️ 실행계획 검증 (fidelity-guard)

## (d) 마스터 통합 + 공백 채움·확정 초대 (별도 섹션)
### 📋 부서별 실행계획 한눈 요약 (목적·시기·담당·자원)
### 🕳️ "언제·누가·무엇으로" 공백 목록 (실행 전 채워야 할 것)
### ⚖️ 과잉·중복 경고 (작은 교회 감당 / 지친 리더)
### 🙏 "담당·자원이 빈 행동이 여기 있습니다. 누가·무엇으로 채우시겠습니까? (못 채우면 미정으로 두되, 실행 전 정해야 합니다.)"
   — [목사 검토·확정 HITL 대기. 확정 전에는 최종 실행계획표를 렌더하지 않는다.]
### (확정 완료 후) 📋 부서별 실행계획표 (xlsx + md)
### ➡️ 다음 단계: resource-aligner(#8)·plan-compiler(#10)로 전달
```

## 원칙
- **(d)에서 반드시 확정을 기다린다.** 공백 목록 제시와 최종 실행계획표 렌더 사이에 목사의 공백 채움·확정 HITL이 있다.
- 공백을 가짜 담당으로 메우지 않는다(전 섹션) — 미정은 미정으로 드러낸다.
- 목표에서 추적되지 않는 행동·지어낸 행사 연계를 만들지 않는다(fidelity-guard 근거·정합 검사).
- 여력 판단·예산·담임 시간은 #8. (#7은 배정·플래그·중복 카운트까지.)
- fidelity-guard 실패 시 (c)에 위반 노출, 해당 분석 재실행(임의 보정 금지).
```
